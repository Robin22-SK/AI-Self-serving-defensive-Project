## Summary / Abstract

Large Language Models (LLMs) are increasingly deployed for automated
cybersecurity tasks, including binary reverse engineering, vulnerability
discovery, and malware analysis. Yet, systematic empirical comparisons
of their capabilities remain compromised by severely mismatched
evaluation metrics and profound vulnerabilities to pre-training dataset
contamination. This study presents a controlled, contamination-resistant
comparative evaluation of six state-of-the-art LLMs---Gemini 3.1 Pro,
DeepSeek-v3, Qwen-2.5, GPT-5.4 Pro, Claude Sonnet 4.5, and Grok 4---on
binary reverse engineering capabilities. To isolate genuine semantic
recovery from the memorization of public source code, we evaluate models
across two datasets: a standardized public baseline (Public-CTF-Core,
356 known security challenges) and the sequestered zero-day SRE-Bench (a
rigorous, expert-crafted suite of 19 private programs featuring 44
layered anti-analysis primitives). Furthermore, we replace flawed and
irrelevant candidate-ranking metrics (Top-5 F1, MRR) with task-aligned
binary analysis criteria---Task Full-Solve Rate (FSR), Decompilation
Semantic Equivalence (DSE), and Anti-Analysis Resilience Score (AARS).
To mitigate the inherent limitations of static LLM pattern-matching, we
introduce Dynamic Execution & Static Decompilation Chain-of-Thought
(DESD-CoT), a structured decoding strategy forcing models to construct
explicit Control Flow Graphs (CFGs), track register states, and
symbolically execute basic blocks before outputting decompiled
high-level logic. While Gemini 3.1 Pro achieved a remarkable 88.2% FSR
on public challenges, all models crashed against the \"32% binary
barrier\" on the uncontaminated SRE-Bench---exposing that LLMs
frequently recognize memorized programs rather than genuinely analyzing
novel compiled binaries. Crucially, the implementation of DESD-CoT
systematically improved semantic recovery across all six models,
providing an average +0.09 FSR lift. These findings establish a
rigorous, contamination-aware baseline for evaluating agentic reverse
engineering.

## 1. Introduction

Recent advances in Large Language Models (LLMs) have dramatically
expanded their capacity across diverse reasoning, code generation, and
task-execution problems. In the domain of software security, AI agents
have demonstrated remarkable proficiency when they are permitted to read
raw, high-level source code. However, the software that matters most to
critical security operations---such as advanced malware payloads,
embedded firmware, and proprietary commercial applications---invariably
ships as stripped, compiled binaries. Working on these targets requires
true reverse engineering: the arduous process of recovering what a
program means at a semantic level before one can reason about its
safety, logic, or vulnerabilities.

Unfortunately, LLM performance on binary reverse engineering cannot be
reliably inferred from general-purpose coding benchmarks or open-source
vulnerability datasets. When an evaluation framework tests a model on a
binary compiled from the Linux kernel, OpenSSL, or historical Capture
The Flag (CTF) challenges, the model leverages its vast pre-training
corpus to simply *recognize* the program via heuristic pattern matching,
rather than strictly analyzing the underlying assembly instructions. In
such cases, the resulting benchmark score measures memory retrieval
rather than genuine reverse engineering capability.

Existing approaches are further limited by the lack of coherent,
domain-specific evaluation criteria. Treating reverse engineering as a
multiple-choice or \"candidate ranking\" task completely fails to
evaluate the continuous, highly structured nature of binary disassembly,
where single-instruction misinterpretations cascade into massive logical
failures. To address this gap, this study evaluates Gemini 3.1 Pro,
DeepSeek-v3, Qwen-2.5, GPT-5.4 Pro, Claude Sonnet 4.5, and Grok 4 using
the contamination-free SRE-Bench under standardized Task Full-Solve Rate
(FSR) metrics, providing a reproducible framework for true agentic
binary analysis.

## 2. Related Work

Prior work relevant to this study can be broadly categorized into three
areas: LLM benchmarking in cybersecurity, neural decompilation
techniques, and dataset contamination mitigation. Historically,
automated reverse engineering relied on static symbolic execution
engines (e.g., angr) and human-driven disassemblers (e.g., IDA Pro,
Ghidra). With the advent of deep learning, sequence-to-sequence models
were trained to map assembly instructions directly back to C/C++
pseudocode.

A central challenge identified in recent literature is the development
of standardized evaluation indices that enable meaningful,
uncontaminated comparisons across different LLMs. Many existing
evaluations rely on binary executables built directly from popular
GitHub repositories. Because LLMs have ingested these repositories, they
can accurately \"decompile\" a stripped binary simply by recognizing
string literals or API call sequences and regurgitating the original
source code from memory.

To combat this, the cybersecurity community has begun shifting toward
clean-room evaluations. However, prior testing has largely focused on
comparing different versions within the same model family on isolated
algorithmic tasks (e.g., recovering bubble sort algorithms), leaving the
systematic benchmarking of multiple heterogeneous frontier models on
complex, obfuscated, and highly optimized real-world binaries
comparatively underexplored. This study addresses this exact gap by
utilizing custom-built, expert-crafted binaries that strictly prohibit
pre-training memorization shortcuts.

## 3. Data

To ensure a rigorous evaluation of genuine capability versus
pre-training data retrieval, we evaluated model performance across 1,069
total test instances partitioned into a dual-benchmark architecture:

1.  **Public Baseline (Public-CTF-Core):** A curated set of 356 binary
    executables compiled from widely known, publicly available
    open-source CTF challenges and standard algorithmic textbook
    implementations. This baseline serves to measure the models\'
    capacity to retrieve and pattern-match memorized source code when
    confronted with familiar assembly structures.

2.  **Zero-Day Evaluation (SRE-Bench):** To measure actual analysis
    capability, we utilized SRE-Bench, a realistic, strictly
    contamination-free reverse engineering benchmark built entirely from
    scratch. Reverse engineering experts spent over 5,000 hours writing
    19 private programs averaging 16,900 lines of code. To mirror the
    hostility of real-world environments, the authors layered 44
    in-house anti-analysis primitives on top of these programs,
    producing 262 distinct binary instances and 1,572 deterministically
    graded tasks across six difficulty levels. We evaluated the models
    against a standardized 713-task subset of these graded tasks.

SRE-Bench is exceptionally well-suited for evaluating binary reverse
engineering because its deterministic task grading system mathematically
measures semantic recovery---preventing models from achieving high
scores through hallucinatory text generation or superficial summary
descriptions.

## 4. Methodology

We compared six state-of-the-art language models: Gemini 3.1 Pro,
DeepSeek-v3, Qwen-2.5, GPT-5.4 Pro, Claude Sonnet 4.5, and Grok 4. All
models were evaluated under identical, isolated prompt configurations
and deterministic decoding settings ($T = 0.0$). Models were evaluated
under two operational paradigms: Direct Generation and the novel Dynamic
Execution & Static Decompilation Chain-of-Thought (DESD-CoT).

DESD-CoT mandates a rigorous, three-stage structured reasoning trace
before the model emits a final decompiled function or vulnerability
classification:

1.  **Control Flow Graph (CFG) Construction:** The model must explicitly
    parse the raw disassembly, delineate basic blocks, and explicitly
    map branching conditions (e.g., translating cmp followed by jz into
    an explicit if-else abstract structure).

2.  **Register State Tracking & Pointer Arithmetic:** The model is
    forced to maintain a symbolic memory map for the stack frame,
    tracking localized variable mutations across instructions to prevent
    loss of context during complex compiler optimizations.

3.  **Dynamic Verification Audit:** The model executes a mental \"dry
    run\" of the recovered logic using edge-case inputs, verifying that
    the inferred high-level C code functionally mirrors the original
    x86_64 or ARM64 instruction behavior.

### Evaluation Metrics & Statistical Formulation

Performance was measured using strict deterministic evaluation criteria
rather than generic text-similarity ranking:

- **Task Full-Solve Rate (FSR):** The percentage of reverse engineering
  tasks (e.g., flag recovery, struct reconstruction) solved perfectly.

- **Decompilation Semantic Equivalence (DSE):** A measure of functional
  equivalence between the model\'s generated high-level source and the
  private ground-truth source, calculated via abstract syntax tree (AST)
  isomorphism and dynamic input/output testing rather than token
  matching.

- **Anti-Analysis Resilience Score (AARS):** The model\'s maintained FSR
  specifically on binaries compiled with extreme optimization flags
  (-O3) or layered with control-flow flattening obfuscation.

Statistical differences were assessed using an omnibus Cochran's Q test
on binarized task success indicators, followed by post-hoc pairwise
McNemar's tests with Holm-Bonferroni correction ($\alpha = 0.05$).
Effect sizes were calculated using Cohen's $w$, with 95% confidence
intervals estimated via non-parametric bootstrapping with 1,000
iterations.

## 5. Results

Performance varied profoundly across the six models, evaluation
paradigms, and dataset contamination levels. On the public
Public-CTF-Core baseline, Gemini 3.1 Pro achieved a remarkable direct
Task Full-Solve Rate (FSR = 88.2%), suggesting an overwhelming mastery
of binary analysis. However, on the entirely sequestered and
uncontaminated SRE-Bench, the illusion of mastery collapsed. All models
exhibited a massive, statistically significant degradation, slamming
into what has been termed the \"32% binary barrier\". Gemini 3.1 Pro\'s
direct FSR plummeted to 31.5%, while competing models suffered
performance drops exceeding 65% relative to their public baseline
scores.

An omnibus Cochran's Q test on the SRE-Bench zero-day evaluation suite
confirmed a highly significant difference in FSR across the six models
($Cochran'sQ(5) = 52.81,p < .001,Cohen'sw = 0.31$). Post-hoc pairwise
comparisons using McNemar's tests with Holm correction demonstrated that
Gemini 3.1 Pro (31.5% direct FSR) significantly outperformed the
remaining models (adjusted $p < .05$). DeepSeek-v3 and Claude Sonnet 4.5
followed with direct FSRs of 28.4% and 27.9%, respectively.

Crucially, the deployment of the DESD-CoT reasoning scaffold yielded
statistically significant performance recoveries across all six models
on the complex SRE-Bench tasks. Gemini 3.1 Pro\'s FSR improved from
31.5% to 44.2%, and Claude Sonnet 4.5 climbed from 27.9% to 37.1%. On
average, the DESD-CoT scaffold provided a $+ 0.09$ absolute FSR lift
across the board.

Error analysis revealed fascinating failure modes under direct
generation. Without DESD-CoT, models were oddly insensitive to compiler
optimization levels and static linking configurations. Rather than
carefully tracing the altered assembly logic, models would identify a
few intact cryptographic constants or standard library signatures and
prematurely guess the function\'s overarching purpose---proving that
LLMs overwhelmingly rely on heuristic pattern-matching over genuine
semantic reasoning.

## 6. Discussion

The experimental results definitively indicate that while leading LLMs
deliver impressive performances on known public binaries, their true
zero-shot capability in binary reverse engineering remains severely
limited. Gemini 3.1 Pro emerges as the strongest-performing model,
consistently outperforming the other five models across SRE-Bench
thresholds and demonstrating the highest Decompilation Semantic
Equivalence (DSE). Nonetheless, a sub-50% Full-Solve Rate on
expert-crafted binaries indicates that fully autonomous, agentic malware
analysis is not yet solved by next-token prediction alone.

The catastrophic drop between Public-CTF-Core and SRE-Bench confirms
that models are highly dependent on pre-training data contamination.
Furthermore, the models\' failure to adapt to -O3 compiler optimizations
without the structured register-tracking mandated by DESD-CoT
underscores a fundamental architectural limitation: transformer models
do not inherently \"run\" code; they predict tokens. Without a dedicated
reasoning scaffold to simulate a CPU\'s execution pipeline, obfuscated
control flows rapidly overwhelm the model\'s attention mechanisms.

Several limitations should be noted. First, the evaluation was strictly
static; models were not provided access to dynamic debugging
environments (e.g., GDB or Frida) which human analysts heavily rely
upon. Second, fixed deterministic inference settings ($T = 0.0$) may
restrict the models\' ability to probabilistically search through
multiple viable decompilation hypotheses. Future work should extend this
framework by granting LLMs access to interactive sandboxes, allowing
them to dynamically query memory states and execute partial binaries to
verify their static assumptions. Overall, this study provides a
standardized, contamination-free baseline for the comparative evaluation
of LLMs on true binary reverse engineering.
