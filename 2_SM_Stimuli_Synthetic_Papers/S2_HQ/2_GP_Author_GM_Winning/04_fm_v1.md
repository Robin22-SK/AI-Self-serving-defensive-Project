## Summary / Abstract

Large Language Models (LLMs) are increasingly deployed as autonomous
agents to discover, compose, and execute tools in digital environments.
However, existing benchmarks evaluate tool use in simplified, idealized
settings---assuming pre-selected tool sets, clean API schemas, and
error-free execution environments. This study presents a controlled,
contamination-resistant comparative evaluation of six LLMs---Gemini 3.1
Pro, DeepSeek-v3, Qwen-2.5, Claude Sonnet 4.5, GPT-5.4 Pro, and Grok
4---on tool discovery and execution under de-idealized real-world
conditions. To isolate true agentic problem-solving from dataset
memorization, we evaluate models across two dynamic environments: a
structured public benchmark derived from AgentGym2 (437 tasks across 27
domains) and a novel, sequestered zero-day environment suite,
AgentGym2-ZeroDay (300 instances featuring un-indexed API registries,
noisy execution outputs, and dynamic parameter schema changes).
Furthermore, we introduce Environment-Aware Tool Disambiguation
(EAT-CoT), an agentic prompting strategy that enforces interactive API
exploration, dry-run schema validation, and dynamic error recovery
before committing state-changing actions. Evaluated using agentic task
completion metrics---Task Success Rate (TSR), Tool Call Accuracy (TCA),
Trajectory Efficiency Ratio (TER), and Error Recovery Rate
(ERR)---Gemini 3.1 Pro achieved the highest baseline TSR (68.4% on
public; 54.1% on zero-day). However, all models exhibited a
statistically significant 14--22% performance drop on the zero-day
benchmark, quantifying the impact of environment memorization. EAT-CoT
systematically improved task success and error recovery across all
models. These findings establish a reproducible, contamination-aware
baseline for real-world agentic evaluation.

## 1. Introduction

Recent advances in Large Language Models (LLMs) have driven their
evolution from passive text generators to active agents capable of
interacting with external tools, databases, and web services. However,
real-world deployment environments are rarely idealized: tool registries
contain hundreds of overlapping or poorly documented APIs, execution
environments return noisy or unexpected responses, and initial action
attempts frequently fail due to runtime parameter mismatches. Evaluating
LLMs under static, single-turn tool-selection setups fails to capture
these operational complexities.

Existing agent benchmarks often evaluate models in simplified contexts
where relevant tools are pre-filtered, API parameters are explicitly
provided in the prompt, and intermediate execution errors are omitted.
To address this gap, this study presents a controlled comparative
evaluation of six heterogeneous LLMs on end-to-end tool discovery and
execution in de-idealized environments. By pairing a public benchmark
(AgentGym2) with an un-indexed zero-day execution suite
(AgentGym2-ZeroDay), and introducing the EAT-CoT agentic framework, this
study isolates genuine exploration, tool composition, and error-recovery
capabilities from training data memorization.

## 2. Related Work

Prior research relevant to this benchmark spans three core domains: LLM
tool-calling evaluations, autonomous agent frameworks, and benchmark
contamination mitigation. Standard tool-use benchmarks (e.g., ToolBench,
Gorilla) focus primarily on single-turn API retrieval or static JSON
schema matching. While these measure short-horizon function calling,
they ignore multi-turn trajectory execution, dynamic environment
feedback, and recovery from unexpected tool failures.

Recent agentic evaluation suites like AgentGym and AgentGym2 have
shifted toward interactive, multi-turn environments. However, because
public agent trajectories are rapidly integrated into web-scale
pre-training datasets, models risk overfitting to specific API naming
conventions and environment shortcuts. This study addresses these
limitations by introducing a dual-benchmark architecture that evaluates
models on both legacy and sequestered zero-day environments using
multi-turn trajectory metrics.

## 3. Data

We evaluated model performance across two distinct agentic environment
suites:

1.  **Public Baseline (AgentGym2-Core):** A standardized set of 437
    multi-turn tasks spanning 27 real-world domains (e.g., data
    analysis, deep web search, e-commerce workflows, and multi-service
    API composition). The environment provides a basic interactive
    action space rather than query-specific, pre-selected tools.

2.  **Zero-Day Evaluation (AgentGym2-ZeroDay):** A novel, sequestered
    execution suite consisting of 300 end-to-end tasks instantiated in
    isolated Docker sandboxes. Tasks feature un-indexed REST/GraphQL
    endpoints, ambiguous parameter documentation, introduced network
    latency, and non-deterministic API error codes designed to test
    real-time tool discovery and parameter schema inference.

Both datasets require models to autonomously discover endpoints, execute
multi-step tool sequences, parse raw environment returns, and adjust
execution trajectories in response to runtime failures.

## 4. Methodology

We compared six language models: Gemini 3.1 Pro, DeepSeek-v3, Qwen-2.5,
Claude Sonnet 4.5, GPT-5.4 Pro, and Grok 4 under deterministic decoding
settings ($T = 0.0$). Models were evaluated under two operational
paradigms: Direct Trajectory Execution and **Environment-Aware Tool
Disambiguation (EAT-CoT)**.

EAT-CoT structures the agentic interaction loop into three explicit
execution phases:

1.  **API Discovery & Schema Intention Mapping:** The agent queries the
    environment registry to inspect documentation, identify candidate
    endpoints, and map task intent to required tool parameters.

2.  **Dry-Run & Parameter Validation:** The agent executes non-mutating
    validation calls (or schema inspection queries) to confirm expected
    payload structures before committing state-changing actions.

3.  **Dynamic Feedback Parsing & Error Recovery:** Upon receiving
    execution returns, the agent explicitly categorizes the response
    (Success, Schema Mismatch, Rate Limit, Runtime Exception) and
    formulates corrective action plans.

Performance was evaluated using four primary trajectory metrics:

- **Task Success Rate (TSR):** The proportion of tasks where the final
  goal state was fully achieved and verified by environment assertions.

- **Tool Call Accuracy (TCA):** The ratio of valid, error-free API
  invocations to total tool calls made during a trajectory.

- **Trajectory Efficiency Ratio (TER):** The ratio of the theoretical
  optimal trajectory length to the model\'s actual step count.

- **Error Recovery Rate (ERR):** The percentage of failed intermediate
  tool calls from which the agent successfully recovered to complete the
  task.

Statistical significance was assessed using an omnibus Cochran's Q test
across repeated task outcomes, followed by post-hoc pairwise McNemar's
tests with Holm correction ($\alpha = 0.05$). Effect sizes were
estimated using Cohen's $h$, and 95% confidence intervals were generated
via non-parametric bootstrapping (1,000 iterations).

## 5. Results

Performance varied significantly across models, task domains, and
environment contamination levels. On the public AgentGym2 benchmark,
Gemini 3.1 Pro achieved the highest overall Task Success Rate (TSR =
68.4%) and Mean Reciprocal Rank for initial tool discovery (MRR =
0.879). However, on the uncontaminated AgentGym2-ZeroDay benchmark,
performance dropped uniformly across all systems: Gemini 3.1 Pro fell to
54.1% TSR, while competing models experienced 15--23% relative drops in
success rates.

An omnibus comparison on the zero-day benchmark revealed statistically
significant performance differences among the six models (Cochran's Q(5)
= 43.82, $p < .001$, Cohen's $w = 0.26$). Post-hoc McNemar's tests with
Holm correction confirmed that Gemini 3.1 Pro maintained a statistically
significant lead over all other models under de-idealized zero-day
conditions (adjusted $p < .05$).

Crucially, implementing the EAT-CoT paradigm yielded statistically
significant improvements across all six models on zero-day tasks,
boosting average TSR by +9.3% and Error Recovery Rate (ERR) by +14.2%.
Fine-grained trajectory analysis indicated that without EAT-CoT, models
frequently suffered from \"hallucinated parameter
persistence\"---repeatedly retrying identical malformed API payloads
after an initial failure---whereas EAT-CoT prompted models to inspect
raw error stacks and adjust parameter types dynamically.

## 6. Discussion

The experimental results demonstrate that autonomous tool discovery and
execution in de-idealized environments remains a challenging frontier
for LLM agents. The uniform performance degradation observed between
public AgentGym2 tasks and AgentGym2-ZeroDay confirms that high
benchmarks on public agent datasets are partially inflated by trajectory
memorization and familiar API schemas.

The sustained performance lead of Gemini 3.1 Pro, paired with the
efficacy of EAT-CoT, highlights two key architectural requirements for
real-world agentic deployment:

1.  **Robust Parameter Inference:** High-performing models excel at
    inferring missing schema details from raw, unformatted API error
    messages.

2.  **Active Trajectory Self-Correction:** Structuring the agent loop to
    separate discovery, dry-run validation, and execution prevents
    catastrophic cascading errors in multi-turn workflows.

Limitations of this study include the reliance on fixed maximum step
budgets (max 20 turns per task) and deterministic decoding ($T = 0.0$),
which may restrict creative problem-solving in open-ended tool
discovery. Future work should explore continuous self-evolution
frameworks (e.g., agent post-training on execution logs) and scale
evaluations to multi-agent collaborative environments with competing
tool registries. Overall, this study provides a rigorous,
contamination-aware benchmark for evaluating LLM agents in real-world
environments.
