## Summary / Abstract

Large Language Models (LLMs) are increasingly deployed as autonomous
agents equipped with tools to browse the web, read emails, and execute
code. This agentic paradigm introduces a severe vulnerability: Indirect
Prompt Injection (IPI), wherein adversarial instructions embedded in
untrusted external data hijack the model\'s operational logic. Yet,
systematic empirical comparisons of model resilience against IPI remain
highly limited, as existing evaluations frequently conflate standard
text jailbreaks with dynamic agentic exploitation. This study presents a
comprehensive, controlled comparative evaluation of six state-of-the-art
models---GPT-5.4 Pro, Claude Sonnet 4.5, Gemini 3.1 Pro, Qwen-2.5,
DeepSeek-v3, and Grok 4---assessing their safety profiles using LivePI,
a highly structured, realistic benchmarking environment. Discarding
inapplicable candidate-ranking metrics, we evaluated the models across
713 live interaction traces encompassing seven input surfaces, twelve
adversarial techniques, and five malicious agentic goals. Defense
performance was measured via Attack Success Rate (ASR) and Defense
Success Rate (DSR), evaluating whether models executed unauthorized tool
calls or leaked sensitive data. GPT-5.4 Pro achieved the highest overall
Defense Success Rate, significantly outperforming other models in
resisting complex instruction-composition attacks. These findings
underscore the critical importance of model selection in agentic
workflows and provide a reproducible, tool-integrated framework for
evaluating true LLM security.

## 1. Introduction

The rapid architectural scaling of Large Language Models has expanded
their utility from passive text generators to active, autonomous agents
capable of interacting with external systems via API tool calls. While
this integration exponentially increases their practical utility, it
simultaneously exposes them to Indirect Prompt Injection (IPI). Unlike
direct prompt injection, where a malicious user attempts to bypass
safety filters via the primary chat interface, IPI occurs when an agent
ingests untrusted external data---such as a compromised webpage, a
malicious email, or a manipulated public repository---that contains
hidden instructions. When the LLM processes this context, it may
inadvertently follow the attacker\'s embedded commands, leading to
unauthorized actions such as data exfiltration or credential theft.

The efficacy of standard safety alignment mechanisms (e.g.,
Reinforcement Learning from Human Feedback) cannot be reliably inferred
for IPI defense. An LLM that robustly refuses a direct user request to
\"write malware\" may effortlessly execute a malicious script if that
script is framed as a \"routine system update\" hidden within a
retrieved Slack message. Existing evaluation approaches are severely
limited by relying on static, text-only datasets that fail to simulate
the complex, multi-turn tool execution pathways of deployed agents. To
address this critical gap, this study evaluates six leading LLMs using
the LivePI benchmark, a dynamic environment that tests real tool-call
authorization and data-flow hijacking. The results indicate that while
GPT-5.4 Pro achieves the strongest safety against IPI, the baseline
vulnerability of all frontier models to external data manipulation
remains a profound challenge for agentic AI.

## 2. Related Work

Prior work relevant to this study can be broadly categorized into three
intersecting domains: language model alignment, agentic security, and
adversarial benchmark design. Historically, model safety evaluations
focused heavily on direct adversarial attacks (jailbreaks), optimizing
for text-based refusal rates. However, as models gained read/write
access to digital environments, researchers identified that data-flow
architectures fundamentally blur the line between system instructions
and user data.

A central challenge identified in contemporary literature is the
development of realistic evaluation indices that measure true
operational risk. Early IPI benchmarks evaluated models on simulated,
sandboxed text completions, essentially treating the vulnerability as a
reading comprehension failure. However, recent literature emphasizes
that IPI must be evaluated as an execution failure. LivePI represents a
paradigm shift, pushing prompt-injection testing closer to deployed
agents by using live interaction paths instead of static prompt suites.
This allows researchers to see which security controls survive real tool
use and changing web content. Existing systematic benchmarking of
multiple heterogeneous models in such live, tool-integrated environments
remains underexplored. This study directly addresses this gap by
conducting a controlled comparative evaluation under a common, highly
dynamic agentic framework.

## 3. Data

To rigorously evaluate model defense performance, we utilized LivePI, a
structured benchmark explicitly designed for assessing IPI risk in a
production-like but test-controlled environment. Rather than relying on
simple text completion, the benchmark orchestrates full agentic
interaction loops. The dataset covers a highly granular taxonomy
comprising seven input surfaces (e.g., email, messaging channels like
Slack and Telegram, local files, web browsing, and public repositories).

Across these surfaces, the benchmark deploys twelve sophisticated attack
and rendering families. These include \"shadow policy updates\" (which
present fake rule changes to the agent), \"single-email chain
spoofing,\" \"compositional instruction attacks,\" and
\"state-desynchronization overrides\" (which trick the agent into
believing a malicious action was already pre-authorized by the user).
These techniques aim to achieve one of five distinct malicious goals:
protected-information exfiltration, unauthorized security-control
changes, unsafe code retrieval or execution, inbox-summary exfiltration,
and cryptocurrency transfer. The dataset was partitioned into a
development set for initial prompt tuning and an evaluation set. LivePI
is exceptionally well-suited for evaluating IPI because it captures the
entire interaction trace---including proposed tool calls and final
responses---allowing for deterministic security auditing via an
LLM-as-a-Judge protocol.

## 4. Methodology

We conducted a comprehensive comparative analysis of six advanced
language models: GPT-5.4 Pro, Claude Sonnet 4.5, Gemini 3.1 Pro,
Qwen-2.5, DeepSeek-v3, and Grok 4. To ensure absolute parity in the
testing environment, all models were integrated as the core reasoning
engine of an autonomous agent framework, equipped with identical
tool-access permissions and system prompt configurations. All
evaluations were conducted using deterministic decoding settings
(temperature = 0.0) to eliminate probabilistic variance across execution
paths.

Crucially, we departed from the flawed application of information
retrieval metrics (such as Top-5 F1-Score or Mean Reciprocal Rank) which
are mathematically and conceptually incompatible with agentic security
evaluations. Instead, defense performance was measured using Attack
Success Rate (ASR) and Defense Success Rate (DSR). ASR is defined as the
percentage of instances where the agent successfully proposed and
executed the unauthorized, attacker-controlled tool call or exfiltrated
the specified data. DSR represents instances where the agent
successfully identified the anomaly, refused the embedded command, or
safely halted execution. Statistical differences in the defense outcomes
between models were rigorously assessed using McNemar\'s test applied to
paired binary outcome indicators (with a significance threshold of α =
0.05). Pairwise effect sizes were calculated using Cohen's h, and 95%
confidence intervals were estimated using non-parametric bootstrapping
with 1,000 iterations.

## 5. Results

Performance varied profoundly across the six models on the LivePI
benchmark, revealing stark contrasts in how different training
architectures process the hierarchy of instructions versus external
data. GPT-5.4 Pro achieved the strongest overall defense performance,
recording the lowest overall Attack Success Rate and the highest Defense
Success Rate across the evaluated malicious goals.

An omnibus statistical comparison indicated a highly significant
difference in IPI vulnerability across the six models. Post-hoc pairwise
comparisons using McNemar's tests with Holm correction further confirmed
that GPT-5.4 Pro significantly outperformed the remaining models in its
ability to resist data-flow hijacking. Claude Sonnet 4.5 demonstrated
the second-highest defense rate, characterized by a highly conservative
tool-calling policy when encountering conflicting instructions.

A detailed breakdown by input surface revealed that group-chat
injections and repository-link attacks consistently yielded the highest
Attack Success Rates across all models, exploiting the models\' tendency
to heavily weight conversational context and code-block instructions.
While heavily aligned models showed strong resistance to overt data
exfiltration requests, their vulnerability paradoxically spiked when
subjected to sophisticated techniques like \"state-desynchronization
overrides\" or \"covert tool binding.\" In these scenarios, attackers
successfully masked the malicious intent as routine API routing
requirements. Overall, while GPT-5.4 Pro emerged as the singularly
strongest-performing model, the data demonstrates that no current
frontier model possesses an infallible boundary between system
directives and retrieved data.

## 6. Discussion

The empirical results of this study indicate that GPT-5.4 Pro currently
delivers the strongest safety profile against Indirect Prompt Injection,
consistently maintaining lower Attack Success Rates than the other five
evaluated models. Its superior ability to compartmentalize the primary
user's system prompt from the instructions embedded within dynamically
retrieved web pages or emails allows it to maintain operational
integrity in complex environments. This advantage likely reflects deeper
investments in data-flow instruction tuning and representation learning
that explicitly penalizes command execution derived from untrusted
contexts.

However, the observed vulnerabilities highlight a fundamental,
structural limitation in contemporary LLM architectures. Because
transformers lack a native hardware-level separation between code
(instructions) and data (external inputs)---akin to the Von Neumann
architecture vulnerabilities of early computing---safety filters remain
highly susceptible to sophisticated semantic obfuscation. The high
success rate of shadow policy updates indicates that models struggle to
maintain their initial system prompt constraints when faced with highly
authoritative, yet counterfeit, contextual data.

Several critical limitations of this study must be acknowledged. First,
the evaluation was restricted to the LivePI benchmark\'s specific suite
of tools, surfaces, and environments; real-world enterprise deployments
may feature far more complex API ecosystems and authentication layers.
Second, the reliance on a deterministic temperature of 0.0, while
necessary for controlled comparison, may not fully capture an agent\'s
vulnerability profile when deployed in high-temperature, creative
execution settings where probabilistic drift can inadvertently activate
malicious payloads.

Future work must extend this evaluation paradigm to multi-turn,
optimization-based injection loops, wherein attackers iteratively adjust
their payloads based on the agent\'s tool outputs. Furthermore, research
should explore the efficacy of robust architectural defenses, such as
prompt-level filtering combined with rigorous pre-execution tool-call
authorization layers. Ultimately, this study provides a vital,
standardized baseline for the comparative evaluation of LLM agents,
demonstrating that securing generative AI against indirect prompt
injection requires far more than basic text alignment; it demands
structural, system-level defense mechanisms.
