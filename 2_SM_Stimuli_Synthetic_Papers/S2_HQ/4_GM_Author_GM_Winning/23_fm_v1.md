## Summary / Abstract

Large Language Models (LLMs) are increasingly deployed for code
generation; however, systematic empirical comparisons of their
capabilities on execution-verified Python programming remain limited.
This study presents a controlled comparative evaluation of six
state-of-the-art LLMs---Gemini 3.1 Pro, DeepSeek-v3, GPT-5.4 Pro,
Qwen-2.5, Claude Sonnet 4.5, and Grok 4---assessing their ability to
generate functionally correct code using the MBPP and DeepMind
CodeContests benchmarks. Across $713$ test instances, we evaluated the
models\' execution pass rates against hidden unit tests and strict
standard I/O checks. Gemini 3.1 Pro achieved the highest overall
Pass@$k$ rates, significantly outperforming comparison models. These
results underscore the critical importance of evaluating LLMs via
sandboxed execution rather than surface-level text similarity, providing
a standardized benchmark for future research in AI-driven software
engineering and automated program synthesis.

## 1. Introduction

Recent advances in Large Language Models (LLMs) have vastly expanded
their operational capacity across reasoning, natural language
generation, and complex task execution. Consequently, the deployment of
LLMs for automated code generation has become a central focus in AI
research. However, an LLM\'s proficiency in Python code generation
cannot be reliably inferred from general-purpose evaluations or static
text-matching metrics, because differences in model architecture,
instruction tuning, and decoding strategies produce substantial
variations in functional correctness.

Existing evaluation approaches are frequently limited by a lack of
coherent execution-based evaluation criteria, making controlled
comparisons across heterogeneous systems exceptionally difficult. When a
model generates code with high semantic overlap to a reference solution
but fails due to a trivial syntax error or an unhandled edge case,
static metrics fail to capture the functional degradation. To address
this fundamental gap, this study evaluates six frontier LLMs on
execution-verified Python code generation utilizing standardized pass
rate metrics (Pass@$k$). The empirical results demonstrate that Gemini
3.1 Pro achieves the strongest performance among the evaluated cohort.
Ultimately, this study provides a reproducible, rigorous methodology for
assessing the functional programming capabilities of LLMs under
verifiable execution constraints.

## 2. Related Work

Prior research relevant to this study intersects three key domains: LLM
capability benchmarking, neural code generation, and test-driven
benchmark design. A persistent challenge identified in contemporary
literature is the development of standardized evaluation indices capable
of measuring functional correctness through actual code execution,
rather than relying on static $n$-gram overlap metrics such as BLEU or
exact-match accuracy.

While existing evaluations have extensively probed iterative
improvements within specific model families, the systematic benchmarking
of multiple heterogeneous frontier models on complex competitive
programming remains comparatively underexplored. Traditional alignment
tests often prioritize foundational code generation, leaving algorithmic
problem-solving capabilities and rigorous I/O constraint adherence
uncalibrated. This study addresses this critical gap by conducting a
controlled empirical evaluation of six distinct proprietary and
open-weight architectures under a unified, execution-verified framework,
effectively isolating the models\' capacity for generating robust,
executable code.

## 3. Data

To rigorously evaluate model robustness, we utilized two established
datasets: the Mostly Basic Python Problems (MBPP) and DeepMind\'s
CodeContests. The MBPP dataset, originally introduced by Google
Research, comprises crowd-sourced, function-level programming tasks
designed to evaluate foundational logic and standard library usage.
Conversely, CodeContests, a dataset famously utilized in the development
of DeepMind\'s AlphaCode, provides significantly harder competitive
programming problems sourced from platforms like Codeforces, requiring
complex algorithmic reasoning and adherence to strict computational
constraints.

Rather than measuring retrieval depth or classification accuracy, this
benchmark requires models to generate standalone Python scripts that are
subsequently executed in a secure, sandboxed environment against hidden
unit tests and standard input/output checks. The combined dataset was
strictly partitioned into a 20% development set utilized for prompt
tuning and an 80% test set reserved for final inference evaluation. This
strategic combination of datasets spans a wide gradient of
difficulty---from entry-level string manipulation to advanced
algorithmic problem-solving---providing a highly robust signal of
execution-verified functional correctness.

## 4. Methodology

We conducted a comprehensive comparative analysis of six advanced
language models: Gemini 3.1 Pro, DeepSeek-v3, GPT-5.4 Pro, Qwen-2.5,
Claude Sonnet 4.5, and Grok 4. To ensure a strictly equitable evaluation
environment, all models were queried under identical zero-shot prompt
configurations and evaluated using unbiased sampling decoding settings
to generate multiple candidate solutions per problem.

Performance was precisely quantified using the **Pass@**$k$ metric as
the primary standard for functional code generation. Given $n$ generated
samples per problem, Pass@$k$ calculates the probability that at least
one of the top $k$ generated scripts passes all hidden unit tests.
Statistical differences between the models\' overall Pass@$1$ and
Pass@$5$ rates were assessed using Cochran\'s $Q$ test on paired binary
outcome indicators, with a strict significance threshold of
$\alpha = 0.05$. Post-hoc pairwise effect sizes were calculated using
McNemar\'s test with the Holm-Bonferroni correction applied to control
for multiple comparisons, and 95% confidence intervals were estimated
utilizing non-parametric bootstrapping with $1,000$ iterations.

## 5. Results

Performance varied significantly across the six models on the combined
MBPP and CodeContests benchmark, highlighting critical differences in
how state-of-the-art models handle algorithmic complexity. Gemini 3.1
Pro attained the highest overall functional correctness across all
evaluation criteria. At both the Pass@$1$ and Pass@$5$ thresholds,
Gemini 3.1 Pro recorded the highest execution success rates,
successfully solving a large majority of the foundational MBPP tasks and
achieving a highly competitive solve rate on the rigorous CodeContests
set.

An omnibus comparison revealed a statistically significant difference in
Pass@$5$ rates across the six models (Cochran\'s $Q(5) = 45.12$,
$p < .001$, Cohen\'s $w = 0.28$). Post-hoc pairwise McNemar\'s tests
incorporating the Holm correction further confirmed that Gemini 3.1 Pro
significantly outperformed the remaining cohort (adjusted $p < .05$).
While models like DeepSeek-v3 and Claude Sonnet 4.5 performed strongly
on the foundational MBPP set, performance gaps widened considerably on
CodeContests, where sophisticated algorithmic reasoning, strict
edge-case handling, and optimized time complexity were required.
Overall, Gemini 3.1 Pro emerged as the most capable model for
execution-verified Python code generation, whereas the comparison models
exhibited specific vulnerabilities regarding complex standard I/O
formatting and memory-time constraints.

## 6. Discussion

The empirical findings of this study indicate that Gemini 3.1 Pro
delivers superior performance on execution-verified Python code
generation, consistently outperforming the other five models across
standard Pass@$k$ thresholds. This distinct advantage likely reflects
rigorous pre-training on code-heavy corpora, specialized reinforcement
learning algorithms designed for logical reasoning, and highly refined
instruction tuning that proactively reduces syntax and logic errors
prior to execution.

Several critical limitations of this study must be acknowledged. First,
the evaluation was deliberately restricted to the MBPP and CodeContests
benchmarks, which primarily focus on standalone, single-file algorithmic
problems. In contrast, real-world software engineering routinely
involves repository-level context, multi-file dependencies, and complex
environments (e.g., SWE-bench). Second, the reliance on fixed zero-shot
inference settings may under-represent true model capabilities compared
to iterative debugging workflows, where an LLM receives immediate
compiler or test feedback and attempts to rectify the code.

Future work must extend this execution-verified evaluation framework to
agentic coding environments and systematically examine whether the
observed performance differences remain stable when models are permitted
iterative test-driven development (TDD) cycles. Ultimately, this study
establishes a standardized, execution-backed baseline for comparing the
functional programming capabilities of modern LLMs, proving that static
evaluation is insufficient for robust automated program synthesis.
